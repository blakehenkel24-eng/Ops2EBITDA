# Issue Tree Builder

## Purpose

Use this skill to structure messy operating problems into clear issue trees.

The goal is to help the user move from vague concern to organized analysis.

## When to Use

Use this skill for:

- Diligence planning
- Root cause diagnosis
- Value creation planning
- Market research
- KPI investigation
- Workstream scoping
- Management meeting prep
- Problem-solving sessions

## Inputs Needed

Ask for or infer:

- Problem statement
- Business context
- Known symptoms
- Desired decision
- Available data
- Constraints
- Timeline

## Output Structure

### Problem Statement

Rewrite the problem clearly.

### Issue Tree

Create 3-5 main branches.

For each branch include:

- Key question
- Sub-questions
- Data needed
- Analysis required
- Potential actions

### Prioritized Analysis Plan

List which branches to test first and why.

## Issue Tree Rules

- Branches should be as MECE as practical.
- Avoid too many branches.
- Do not confuse symptoms with causes.
- Focus on decision-relevant questions.
- Make each branch testable.
- Include data needed.

## Common Branch Examples

Revenue problem:
- Market demand
- Customer retention
- Sales productivity
- Pricing / packaging
- Product / service fit

Margin problem:
- Price realization
- Cost inflation
- Product / customer mix
- Labor productivity
- Procurement / vendor terms

Cash problem:
- Receivables
- Inventory
- Payables
- Billing accuracy
- Forecasting discipline

## Example Prompt

Use the Issue Tree Builder skill. Structure the problem: “EBITDA is below plan despite revenue being on plan.” Build a MECE issue tree and prioritized analysis plan.

## Quality Checklist

- Is the problem statement clear?
- Are branches non-overlapping enough?
- Are sub-questions testable?
- Is data needed identified?
- Is there a prioritized analysis plan?
