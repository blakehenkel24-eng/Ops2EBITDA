# Recovery Plan Builder

## Purpose

Use this skill to build a recovery plan when a workstream, KPI, or value creation initiative is off track.

A recovery plan should be specific, time-bound, and focused on root cause.

## When to Use

Use this skill for:

- Missed milestones
- Value capture slippage
- KPI underperformance
- Delayed integration
- Failed pricing action
- Procurement savings shortfall
- Dashboard build delay
- Working capital deterioration
- Red / Amber workstream status

## Inputs Needed

Ask for or infer:

- Original target
- Current status
- Variance
- Root cause / suspected cause
- Owner
- Timeline
- Value at risk
- Current blockers
- Decisions needed

## Output Structure

### Recovery Summary

State what is off track and why it matters.

### Recovery Plan

| Issue | Root Cause | Corrective Action | Owner | Due Date | Proof Point | Escalation Needed |
|---|---|---|---|---|---|---|

### Value at Risk

Estimate or describe the value impact. Caveat if data is missing.

### Next 2 Weeks

List immediate actions.

## Recovery Rules

- Do not write generic “increase focus” actions.
- Identify root cause.
- Identify owner.
- Define proof point.
- Include escalation if needed.
- Separate temporary fix from structural fix.

## Example Prompt

Use the Recovery Plan Builder skill. This integration workstream is 4 weeks behind and synergy validation is slipping. Build a recovery plan with root causes, corrective actions, owners, proof points, and escalation needs.

## Quality Checklist

- Is root cause addressed?
- Are actions specific?
- Is value at risk visible?
- Are owners and dates included?
- Are proof points measurable?
- Is escalation clear?
