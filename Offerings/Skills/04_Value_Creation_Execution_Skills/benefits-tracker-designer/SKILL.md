# Benefits Tracker Designer

## Purpose

Use this skill to design a benefits tracking structure for value creation initiatives.

The goal is to distinguish theoretical value from validated EBITDA, cash, or operational impact.

## When to Use

Use this skill for:

- Procurement savings
- Pricing actions
- Headcount savings
- Working capital release
- Revenue growth initiatives
- Integration synergies
- Cost reduction programs
- Transformation PMO
- Board reporting

## Inputs Needed

Ask for or infer:

- Initiative type
- Target benefit
- Baseline
- Calculation method
- Owner
- Timing
- Validation source
- Finance sign-off requirements
- Leakage risks

## Validation Rules

- Gross opportunity is not value capture.
- Savings must be tied to baseline.
- EBITDA impact should be validated by finance.
- Cash release should be separate from EBITDA.
- Cost avoidance should not be counted as EBITDA unless clearly supportable.
- One-time savings should be separated from run-rate savings.

## Example Prompt

Use the Benefits Tracker Designer skill. Design a benefits tracker for a procurement savings program with gross savings, leakage, net savings, run-rate EBITDA, finance validation, and status.

## Quality Checklist

- Does the tracker separate gross, net, realized, and validated?
- Is validation source defined?
- Is finance sign-off included?
- Is cash separated from EBITDA?
- Are leakage risks visible?
